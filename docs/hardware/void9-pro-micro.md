# 键盘候选方案：void9 + Pro Micro

整理日期：2026-10-23。本文把 [void9](https://github.com/victorlucachi/void9) 作为本项目的一个 3×3 键盘候选方案，说明如何配合电脑端实现语音输入。

**本方案优先复用已有九键键盘，键盘发送操作事件，电脑负责麦克风采集、语音识别和文字输入。** 它不确定整个项目的硬件路线，ESP32 等其他主控方案可以并列探索。

### 职责分工

| 部分 | 负责什么 | 尚需完成什么 |
| --- | --- | --- |
| void9 / Pro Micro | 扫描按键，发送语音键按下、释放以及发送、取消等操作 | 确认实物接线与固件，设计映射并验证按键事件 |
| 电脑端配套程序或经验证可用的输入工具 | 接收操作、采集电脑麦克风、调用语音识别、展示文字 | 选定系统与识别方案，验证权限、录音状态和文字输入 |
| 目标桌面应用 | 接收用户确认后的文字 | 验证输入、焦点和发送方式；不能假设自制键盘自动具备官方 Micro 原生集成 |

语音键的建议行为是：**按下开始录音，松开结束录音，识别完成后预览文字，由用户选择编辑、取消或发送。** 结束录音与提交文字应是两个明确动作。

### 候选九键布局

| 左 | 中 | 右 |
| --- | --- | --- |
| 任务 1 | 任务 2 | 任务 3 |
| 上一个 | 按住说话 | 下一个 |
| 取消 | 功能层 | 发送 |

这只是用于讨论的映射。任务键、上一个和下一个需要定义具体语义，并验证目标软件的接口或快捷键；不表示这些动作已能控制 Codex。也可以先用普通编辑快捷键替代任务键。

## 3. 实现路径与最小验证

### 阶段一：保留键盘，验证语音输入闭环

1. 确认现有设备的接线、固件和键位，保留可恢复的配置。
2. 验证语音键能让电脑区分按下与释放。可以先评估普通键码或快捷键；目标输入工具需确实支持所需触发方式。
3. 使用电脑麦克风完成录音与识别，显示识别结果。
4. 验证取消、编辑和手动提交到目标应用；提交前确认焦点正确。
5. 验证长按时不会因按键重复而反复开始录音，断连或丢失释放事件时能结束录音并恢复状态。

QMK 提供按下/释放事件回调，因此可以实现自定义语音键控制逻辑。但这只是固件机制的依据，不代表已与某款输入工具完成适配。[S4]

### 阶段二：需要时增加双向控制

如果普通快捷键无法可靠表达设备身份、录音状态或反馈，可评估 QMK Raw HID 与自研桌面程序。QMK 官方文档说明 Raw HID 支持键盘与电脑双向通信，同时需要电脑端程序参与。[S5]

采用此路线前，需验证固件空间、VIA/Vial 共存方式、协议格式与断线恢复。首版不通过这条控制通道传输麦克风音频，也不承诺已有逐键 RGB、屏幕或任务状态反馈。

### 建议验收项

- [ ] 按住语音键只开始一次录音，松开后停止。
- [ ] 中文识别结果可预览、编辑和取消。
- [ ] 用户确认后才向目标应用输入或发送文字。
- [ ] 断连、识别失败或麦克风权限不足时，状态明确且可以重新开始。
- [ ] 普通九键及功能层不受语音控制逻辑干扰。

以上均为后续原型的验收建议，本次未执行硬件或语音测试。

## 4. 复用前需要核对的硬件与固件

**新旧列引脚顺序不同。** 上游说明 2022 年 10 月以前的构建使用 `D1、D0、D4`；当前配置为列 `D1、D4、D0`，行 `F4、F5、F6`，二极管方向为 `COL2ROW`。现有设备应以实际接线为准，不能直接刷入预编译固件。[S1][S2]

上游固件定义两路编码器，但是否安装仍取决于具体装配。Vial 版本为适应 ATmega32U4 的固件空间关闭了 RGB、OLED 等功能，后续若增加功能需要重新评估资源和编译结果，不能把默认键图中出现相关键码当作硬件已经支持。[S1][S3]

Redux 目录中存在不同控制器的安装支架，这是机械适配资料，不代表相应主控已经有可直接使用的固件。当前只确认用户已有 Pro Micro，外壳版本、编码器配置与固件版本均待确认。[S1]

## 5. 与 ESP32 等方案的关系

| 比较项 | void9 + Pro Micro 候选方案 | ESP32 等其他候选方案 |
| --- | --- | --- |
| 起点 | 复用已有九键键盘和制作经验 | 独立评估芯片、开发板与键盘结构 |
| 本文语音路径 | 使用电脑麦克风和电脑端识别 | 可探索电脑端音频或设备采集，尚未决定 |
| 连接方式 | 先评估现有 USB 键盘控制路径 | USB 或无线等连接能力需按具体型号核实 |
| 固件 | 从现有设备及上游 QMK 配置出发验证 | 固件栈待选，不默认沿用 QMK |
| 可共享的设计 | 录音起止、预览、取消、确认发送的交互语义 | 可以复用交互语义，具体事件协议与实现待定 |
| 当前状态 | 已形成书面方案，未完成端到端验证 | 候选方向，尚未开展具体选型 |

这里不对“ESP32”整个系列作统一的 USB、音频或固件兼容承诺。选择具体芯片与开发板后，再形成独立方案文档；本方案也不因此变成项目唯一实现。
